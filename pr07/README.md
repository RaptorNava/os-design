## 1. Сводная таблица механизмов IPC
| Механизм | Нужна ли синхронизация? | Объём данных | Время передачи (10⁷ чисел / ~76MB) |
| :--- | :--- | :--- | :--- |
| **Pipe** | Да (автоматическая блокировка) | Произвольный (поток байт) | Медленно (сериализация / пикл + копирование) |
| **Unix Sockets** | Да | Произвольный | Умеренно (через буферы ядра) |

## 2. Контрольные вопросы
1. **Почему разделяемая память — самый быстрый и самый опасный механизм IPC?**
   - *Быстрый:* данные не копируются между процессами и не проходят через системные вызовы ядра (zero-copy).
   - *Опасный:* ОС не предоставляет встроенной защиты от одновременной записи, что приводит к состоянию гонки (race condition) и разрушению данных без явной синхронизации программистом.
2. **Что произойдёт при записи в pipe, у которого закрыты все читающие концы?**
   - Ядро пошлет процессу-писателю сигнал `SIGPIPE`, который по умолчанию аварийно завершает процесс.
