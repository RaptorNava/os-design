# Практическая работа № 10. Страничная организация памяти

## 1. Вариант A. Базовая трансляция адресов
* **Размер страницы:** $1\text{ КБ} = 1024\text{ Б}$ ($2^{10}$).
* **Формулы:** $\text{page} = \lfloor \text{addr} / 1024 \rfloor$, $\text{offset} = \text{addr} \bmod 1024$, $\text{phys\_addr} = \text{frame} \times 1024 + \text{offset}$.
* **Ручной расчёт контрольных адресов:**
  1. `1200` $\to$ стр. $1$, смещ. $176 \to$ кадр $2 \to$ физ. адрес: $2 \times 1024 + 176 = \mathbf{2224}$.
  2. `3100` $\to$ стр. $3$, смещ. $28 \to$ кадр $0 \to$ физ. адрес: $0 \times 1024 + 28 = \mathbf{28}$.
  3. `5000` $\to$ стр. $4 \to$ кадр отсутствует (`-`) $\to$ **Page Fault (Страничный отказ)**.

**Почему размер страницы выбирают степенью двойки?**
Степень двойки ($2^n$) позволяет аппаратному MMU разделять виртуальный адрес на номер страницы и смещение через быстрые **побитовые сдвиги и маски (`AND`)**, заменяя медленные операции деления и взятия остатка.

## 2. Вариант B. Моделирование TLB и двухуровневой таблицы
* **Формула EAT (Эффективное время доступа):**
  $$\text{EAT} = h \cdot (T_{\text{TLB}} + T_{\text{MEM}}) + (1 - h) \cdot (T_{\text{TLB}} + 2 \cdot T_{\text{MEM}})$$
  * При $h = 0\% \to 210\text{ нс}$, при $h = 95\% \to 115\text{ нс}$, при $h = 99\% \to 111\text{ нс}$ ($T_{\text{TLB}} = 10\text{ нс}$, $T_{\text{MEM}} = 100\text{ нс}$).
* **TLB Hit Rate vs Размер ($K$):** При пространственно-временной локальности резкий рост доли попаданий происходит, когда рабочий набор страниц полностью помещается в емкость TLB.
* **Двухуровневая таблица страниц:** Без TLB одна трансляция требует **3 обращений к RAM** (каталог $\to$ таблица 2-го уровня $\to$ данные).

## 3. Вариант C. Эксперименты в ОС Linux
* **C.1 (`/proc/self/pagemap`):** Требует прав `root` (`sudo`) для защиты от атак по сторонним каналам (например, Rowhammer). Программа считывает 64-битный дескриптор PTE, проверяет бит присутствия и вычисляет PFN.
* **C.2 (Разделяемые страницы через `mmap`):** Два процесса проецируют один файл с флагом `MAP_SHARED` по **разным виртуальным адресам**, но `/proc/self/pagemap` доказывает, что их физический кадр (`PFN`) идентичен.
* **C.3/C.4 (TLB-промахи и Huge Pages):** Обход памяти с шагом, равным размеру страницы ($4096\text{ Б}$), вызывает массовые TLB-промахи из-за превышения емкости TLB. Включение Transparent Huge Pages (`MADV_HUGEPAGE`, страницы по $2\text{ МБ}$) резко сокращает число записей и ускоряет работу.

## Контрольные вопросы
1. **Почему без TLB страничная организация замедлила бы каждое обращение к памяти вдвое и более?**
   Таблица страниц находится в RAM. Без кэширования в TLB процессору требуется делать от 1 до нескольких дополнительных обращений к памяти только для чтения таблиц трансляции перед каждым реальным доступом к данным.
2. **Что хранится в записи таблицы страниц (PTE) помимо номера кадра?**
   Бит присутствия (`Present`), биты прав доступа (`R/W/X`, `User/Supervisor`), бит модификации (`Dirty`), бит обращения (`Accessed`) и флаги управления кэшированием.
