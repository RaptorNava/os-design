# Отчет по системным вызовам (Python vs Cat)

## Анализ работы `python3 hello.py data/01.log`

1. **Общее количество системных вызовов:**
   В ходе работы скрипта было зафиксировано **[553]** системных вызовов.

2. **Вызовы, относящиеся к работе с файлом `data/01.log`:**
   Непосредственно к файлу относится **всего 1–2 системных вызова** (`newfstatat` или `statx`), которые запрашивают у ядра Linux метаданные файла (его размер). Чтение самого содержимого (`read`) не выполняется, так как скрипт только измеряет размер.

3. **Почему остальные вызовы — это накладные расходы интерпретатора?**
   Подавляющее большинство системных вызовов (~99%) требуется виртуальной машине Python (PVM) для своего запуска и инициализации:
   * Загрузка динамических библиотек C-runtime (`openat`, `mmap`, `close` для файлов `.so`).
   * Поиск, открытие и проверка встроенных модулей Python (модули `sys`, `os`, `codecs` и др.).
   * Настройка виртуальной памяти и локали системы (`brk`, `mmap`, `mprotect`).

## Сравнение `cat` и `python3 hello.py`

* **Количество системных вызовов `cat`:** [120]
* **Количество системных вызовов `python3`:** [553]

### Вывод:
Утилита `cat` — это скомпилированная бинарная программа на C. Ей требуется минимальный набор системных вызовов для инициализации системной библиотеки `libc` и прямого ввода-вывода (`openat`, `fstat`, `read`, `write`). 

Интерпретатор Python же является тяжелой средой выполнения, которой перед стартом пользовательского кода необходимо найти и загрузить десятки стандартных модулей и настроить виртуальную машину, из-за чего количество системных вызовов различается более чем в 10 раз.
