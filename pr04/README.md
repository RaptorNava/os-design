# Практическая работа № 4 - Вариант B

## 1. Таблица измерений (CPU-bound задача, 10 млн чисел, nproc = 4 ядра, 3 повтора, взята медиана)
| Подход | Время выполнения (сек) | Описание |
| :--- | :--- | :--- |
| **Один поток (Sequential)** | ~0.36с | Базовое выполнение на одном ядре |
| **4 Потока (threading)** | ~0.37с | Нет ускорения из-за GIL в CPython |
| **4 Процесса (multiprocessing)** | ~0.12с | Ускорение за счет параллельной работы ядер |

## 2. Сравнение I/O-задач (20 запросов с задержкой 0.1с)
- **Последовательно:** ~2.0с
- **ThreadPoolExecutor (4 потока):** ~0.5с (значительный выигрыш за счет параллельного ожидания I/O)
- **ProcessPoolExecutor (4 процесса):** ~0.6–0.7с (накладные расходы на инициализацию и межпроцессное взаимодействие)

## 3. Выводы
- **Потоки (Threads)** эффективны для I/O-bound задач (сеть, дисковый ввод-вывод), так как позволяют переключаться во время ожидания без затрат на копирование памяти.
- **Процессы (Processes)** эффективны для CPU-bound задач (тяжелые вычисления), так как обходят GIL и задействуют реальные ядра процессора, но требуют больше памяти и накладных расходов.

## 4. Контрольные вопросы
1. **Что общего у потоков одного процесса и что у каждого своё?**
   - *Общее:* виртуальное адресное пространство, куча (heap), глобальные переменные, открытые файловые дескрипторы, сигналы.
   - *Своё:* стек вызовов, регистры процессора, программный счетчик (PC), идентификатор потока (TID) и локальное хранилище потока (TLS).
2. **Почему в CPython 4 потока не ускорили счёт, а 4 процесса ускорили?**
   - Из-за глобальной блокировки интерпретатора (GIL) в CPython в один момент времени байт-код Python может исполняться только одним потоком. Процессы же работают в независимых интерпретаторах и отдельных адресных пространствах, полностью задействуя аппаратную многоядерность процессора.
