# Практическая работа №01 (Вариант B)

## Цель работы
Изучение управления пользователями, группами и правами доступа в Linux, экспериментальная проверка прав на удаление файлов, а также настройка пользовательского окружения Bash.

## Порядок выполнения и проверки

1. **Создание группы и пользователя:**
bash
sudo groupadd developers
sudo useradd -m -s /bin/bash -g developers student2
sudo passwd student2
2. **Создание каталога и настройка прав:**
bash
sudo mkdir -p /srv/shared
sudo chown root:developers /srv/shared
sudo chmod 2775 /srv/shared
3. **Эксперимент с файлом:**
- От имени `student2` создан файл `/srv/shared/test_by_student2.txt`.
- От имени основного пользователя (`raptor`, входящего в группу `developers`) выполнен попытка удаления файла:
bash
rm /srv/shared/test_by_student2.txt
## Результат и объяснение эксперимента
Файл от имени основного пользователя успешно удален без применения `sudo`.

**Объяснение:** В ОС Linux возможность удаления файла определяется правами записи (`w`) **на родительский каталог**, а не на сам файл. Каталог `/srv/shared` принадлежит группе `developers` и имеет права `2775` (`rwxrwxr-x`). Все участники группы `developers` имеют право модифицировать содержимое каталога, включая добавление и **удаление любых файлов** внутри него.

## Ответы на контрольные вопросы

### 1. Чем `su` отличается от `sudo`?
- **`su` (Switch User):** Полностью переключает текущий сеанс на другого пользователя (по умолчанию root). Требует ввода **пароля того пользователя, на которого переключаются**.
- **`sudo` (SuperUser Do):** Выполняет отдельную команду с правами суперпользователя. Требует ввода **пароля текущего пользователя**, а доступ регламентируется файлом `/etc/sudoers`.

### 2. Почему в Ubuntu по умолчанию заблокирован вход под `root`?
- **Безопасность:** Минимизируется риск случайного повреждения системы ошибочной командой с полномочиями суперпользователя.
- **Аудит:** Действия через `sudo` логируются в `/var/log/auth.log`, что позволяет отследить, кто выполнял команды.
- **Защита от атак:** Заблокированный root предотвращает атаки перебором паролей (brute-force) по SSH.
